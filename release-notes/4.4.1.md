## RabbitMQ 4.4.1

RabbitMQ `4.4.1` is a maintenance release in the `4.4.x` [release series](https://www.rabbitmq.com/release-information).

It is **strongly recommended** that you read [4.4.0 release notes](https://github.com/rabbitmq/rabbitmq-server/releases/tag/v4.4.0)
in detail if upgrading from a version prior to `4.4.0`.

### Minimum Supported Erlang Version

The minimum supported Erlang version for this release series is `27.0`.

[RabbitMQ and Erlang/OTP Compatibility Matrix](https://www.rabbitmq.com/docs/which-erlang) has more details on Erlang version requirements for RabbitMQ.

Nodes **will fail to start** on older Erlang releases.


## Changes Worth Mentioning

Release notes can be found on GitHub at [rabbitmq-server/release-notes](https://github.com/rabbitmq/rabbitmq-server/tree/v4.4.x/release-notes).

### Core Server

#### Bug Fixes

 * Definition import on boot could hang on Erlang 28 because of a missing dependency
   between boot steps.

   GitHub issues: [#17914](https://github.com/rabbitmq/rabbitmq-server/issues/17914), [#17915](https://github.com/rabbitmq/rabbitmq-server/pull/17915)

 * Virtual host records written by older versions could have their limits set to `undefined`,
   which made definition export fail.

   GitHub issue: [#18137](https://github.com/rabbitmq/rabbitmq-server/pull/18137)

 * Definition export no longer includes bindings to exclusive queues, and definition import
   skips bindings to `amq.*` queues with a warning instead of failing.

   Contributed by @gomoripeti.

   GitHub issue: [#17838](https://github.com/rabbitmq/rabbitmq-server/pull/17838)

 * Definition export no longer includes bindings of queues that were concurrently deleted,
   and definition import skips bindings of missing server-named queues.

   GitHub issue: [#17841](https://github.com/rabbitmq/rabbitmq-server/pull/17841)

 * A quorum queue leader health check could report a queue with a leader as unhealthy, for example
   after a leadership change or when the node running the check did not host a replica.

   Contributed by @Ayanda-D.

   GitHub issue: [#18274](https://github.com/rabbitmq/rabbitmq-server/pull/18274)

 * When a new quorum queue member is started, the lowest `ra` machine version among the
   reachable members is now used.

   GitHub issues: [#18053](https://github.com/rabbitmq/rabbitmq-server/issues/18053), [#18055](https://github.com/rabbitmq/rabbitmq-server/pull/18055)

 * The quorum queue message expiration timer is now capped at one year.

   GitHub issue: [#17815](https://github.com/rabbitmq/rabbitmq-server/pull/17815)

 * The metadata store now waits for Raft members with a capped timeout, which avoids an endless
   retry loop in some operational scenarios.

   GitHub issues: [#18114](https://github.com/rabbitmq/rabbitmq-server/issues/18114), [#18233](https://github.com/rabbitmq/rabbitmq-server/pull/18233)

 * Classic queue CRC32 checksums are now calculated in a way that is compatible with future Erlang releases.

   GitHub issues: [#18161](https://github.com/rabbitmq/rabbitmq-server/issues/18161), [#18216](https://github.com/rabbitmq/rabbitmq-server/pull/18216)

 * Classic queues: a crash report for a deleted queue now shows the original error.

   GitHub issue: [#18208](https://github.com/rabbitmq/rabbitmq-server/pull/18208)

 * Message conversion between AMQP 0-9-1 and AMQP 1.0 no longer fails on `decimal`
   and `null` header values, nor on `float`, `double` and `null` annotation values
   set by the AMQP 1.0 `modified` outcome.

   GitHub issues: [#18042](https://github.com/rabbitmq/rabbitmq-server/pull/18042), [#18156](https://github.com/rabbitmq/rabbitmq-server/pull/18156)

 * Hourly log file rotation (for example, `log.file.rotation.date = $H30`) never rotated the file.

   Contributed by @bellCold.

   GitHub issues: [#7562](https://github.com/rabbitmq/rabbitmq-server/issues/7562), [#18263](https://github.com/rabbitmq/rabbitmq-server/pull/18263)

 * Streams now handle non-string `x-stream-filter-value` values gracefully.

   GitHub issue: [#18147](https://github.com/rabbitmq/rabbitmq-server/pull/18147)

 * AMQP 0-9-1 header and argument tables are validated more strictly.

   GitHub issues: [#18213](https://github.com/rabbitmq/rabbitmq-server/pull/18213), [#18243](https://github.com/rabbitmq/rabbitmq-server/pull/18243)

 * AMQP 1.0 frames are validated more strictly.

   GitHub issues: [#17954](https://github.com/rabbitmq/rabbitmq-server/pull/17954), [#18029](https://github.com/rabbitmq/rabbitmq-server/pull/18029)

 * AMQP 1.0 SQL filter expressions are evaluated more defensively.

   GitHub issue: [#18302](https://github.com/rabbitmq/rabbitmq-server/pull/18302)

 * An AMQP 1.0 session no longer crashes when its writer process has already exited
   during connection closure.

   GitHub issue: [#18070](https://github.com/rabbitmq/rabbitmq-server/pull/18070)

 * Credential expiry handling improvements.

   GitHub issues: [#17857](https://github.com/rabbitmq/rabbitmq-server/pull/17857), [#17979](https://github.com/rabbitmq/rabbitmq-server/pull/17979), [#17980](https://github.com/rabbitmq/rabbitmq-server/pull/17980)

 * [Proxy Protocol](https://www.rabbitmq.com/docs/networking#proxy-protocol) handling improvements.

   GitHub issue: [#17995](https://github.com/rabbitmq/rabbitmq-server/pull/17995)

 * Dead lettering validates its targets more strictly.

   GitHub issue: [#18195](https://github.com/rabbitmq/rabbitmq-server/pull/18195)

 * Channels now send `channel.close-ok` with a short socket write timeout.

   GitHub issue: [#18242](https://github.com/rabbitmq/rabbitmq-server/pull/18242)

#### Enhancements

 * AMQP 0-9-1 channels now use flow control when sending to the connection's socket writer process.

   GitHub issue: [#18049](https://github.com/rabbitmq/rabbitmq-server/pull/18049)

 * Closing a non-AMQP 0-9-1 connection (for example, an MQTT, STOMP, stream or AMQP 1.0 connection)
   is now cheaper on nodes with many tracked channels.

   GitHub issue: [#18139](https://github.com/rabbitmq/rabbitmq-server/pull/18139)

 * Policy names and definitions, as well as global runtime parameter names and values, are now
   subject to size limits. The defaults are well above realistically used values.

   ```ini
   # the defaults are 1 KiB for the name and 64 KiB for the definition
   policies.max_name_length = 1024
   policies.max_definition_size = 65536

   # the defaults are 1 KiB for the name and 128 KiB for the value
   runtime_parameters.global.max_name_length = 1024
   runtime_parameters.global.max_value_size = 131072
   ```

   GitHub issues: [#18221](https://github.com/rabbitmq/rabbitmq-server/pull/18221), [#18261](https://github.com/rabbitmq/rabbitmq-server/pull/18261)

 * Stream segment files now enforce a minimum size of 4,096 bytes. Note that virtually all installations
   use and should use values in megabytes, not kilobytes.

   GitHub issue: [#18023](https://github.com/rabbitmq/rabbitmq-server/pull/18023)

### Management Plugin

#### Bug Fixes

 * HTTP API endpoints that accept JSON request bodies now require the `content-type` header to be `application/json`.

   GitHub issue: [#18196](https://github.com/rabbitmq/rabbitmq-server/pull/18196)

 * Several HTTP API endpoints that previously required previleged tagging of the use now require the `administrator` tag.

   GitHub issues: [#18206](https://github.com/rabbitmq/rabbitmq-server/pull/18206), [#18301](https://github.com/rabbitmq/rabbitmq-server/pull/18301), [#18065](https://github.com/rabbitmq/rabbitmq-server/pull/18065)

 * Publishing via the HTTP API is now refused when a [resource alarm](https://www.rabbitmq.com/docs/alarms) is in effect.

   GitHub issue: [#18057](https://github.com/rabbitmq/rabbitmq-server/pull/18057)

 * Queue, stream and exchange names that are not valid UTF-8 are now rejected with a `400 Bad Request`.

   GitHub issues: [#18215](https://github.com/rabbitmq/rabbitmq-server/pull/18215), [#18234](https://github.com/rabbitmq/rabbitmq-server/pull/18234)

 * CORS handling improvements.

   GitHub issue: [#18032](https://github.com/rabbitmq/rabbitmq-server/pull/18032)

 * An example `rabbitmq.conf` file could not be generated from the management plugin's schema.

   Contributed by @wn1331.

   GitHub issues: [#17941](https://github.com/rabbitmq/rabbitmq-server/issues/17941), [#18256](https://github.com/rabbitmq/rabbitmq-server/pull/18256)

#### Enhancements

 * The polling consumer (`POST /api/queues/{vhost}/{name}/get`) endpoint now limits how many messages
   and payload bytes a single request can return:

   ```ini
   # the defaults are 1000 messages and 64 MiB
   management.polling_consumer.max_messages = 1000
   management.polling_consumer.max_payload_bytes = 67108864
   ```

   GitHub issue: [#17953](https://github.com/rabbitmq/rabbitmq-server/pull/17953)

 * HTTP API JSON request body decoding now uses less memory with larger payloads.

   GitHub issue: [#18152](https://github.com/rabbitmq/rabbitmq-server/pull/18152)

### Shovel Plugin

#### Bug Fixes

 * Non-administrator users now must provide a password (or a token) in [direct URIs](https://www.rabbitmq.com/docs/uri-spec),
   including the URIs that use their own username.

   Administrators can still use direct URIs without a password.

   GitHub issue: [#18004](https://github.com/rabbitmq/rabbitmq-server/pull/18004)

 * A shovel now drops messages that the destination refuses because they exceed its maximum message size,
   instead of restarting over and over.

   GitHub issue: [#18279](https://github.com/rabbitmq/rabbitmq-server/pull/18279)

 * Deleting a shovel whose peer does not respond now takes at most about 10 seconds per side.

   GitHub issue: [#18086](https://github.com/rabbitmq/rabbitmq-server/pull/18086)

 * AMQP 1.0 shovels no longer leave connections behind when connection setup times out.

   GitHub issue: [#18095](https://github.com/rabbitmq/rabbitmq-server/pull/18095)

#### Enhancements

 * `reconnect-delay` is now validated more strictly.

   GitHub issue: [#18110](https://github.com/rabbitmq/rabbitmq-server/pull/18110)

 * Connection timeout is now limited to 180 seconds.

   GitHub issue: [#18037](https://github.com/rabbitmq/rabbitmq-server/pull/18037)

### MQTT Plugin

#### Bug Fixes

 * Retained messages were lost when the metadata store was migrated to Khepri.

   GitHub issues: [#18185](https://github.com/rabbitmq/rabbitmq-server/issues/18185), [#18186](https://github.com/rabbitmq/rabbitmq-server/pull/18186)

 * A retained Will message with a Will Delay Interval could not be delivered to subscribers.

   Contributed by @himanxhugaur.

   GitHub issue: [#18225](https://github.com/rabbitmq/rabbitmq-server/pull/18225)

#### Enhancements

 * The number of topic filters and user properties per packet is now limited:

   ```ini
   # the defaults are 512
   mqtt.max_topic_filters_per_packet = 512
   mqtt.max_user_properties_per_packet = 512
   ```

   GitHub issue: [#18025](https://github.com/rabbitmq/rabbitmq-server/pull/18025)

 * Message expiration is now limited to 10 years, consistent with other protocols.

   Contributed by @himanxhugaur.

   GitHub issue: [#18141](https://github.com/rabbitmq/rabbitmq-server/pull/18141)

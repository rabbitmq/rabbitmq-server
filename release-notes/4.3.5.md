## RabbitMQ 4.3.5

RabbitMQ `4.3.5` is a maintenance release in the `4.3.x` [release series](https://www.rabbitmq.com/release-information).


## Changes Worth Mentioning

### Stream Plugin

#### Enhancements

 * Before a stream client connection completes authentication and authorization (that is, before
   a successful `open`), the server now enforces a low `frame_max` ceiling instead of
   the full configured value. The default, 8192 bytes, is high enough to accommodate realistic
   [JWT tokens](https://www.rabbitmq.com/docs/oauth2) used with SASL PLAIN authentication,
   and mirrors a mechanism already in place for AMQP 0-9-1 connections. It can be adjusted
   with the new `stream.initial_frame_max` setting.

   GitHub issue: [#17053](https://github.com/rabbitmq/rabbitmq-server/pull/17053)

 * `Deliver` frames sent to stream consumers are now checked against the connection's
   negotiated `frame_max`.

   GitHub issue: [#17083](https://github.com/rabbitmq/rabbitmq-server/pull/17083)


### Logging 

#### New `user` Logging Category for Authentication Events

Authentication events are now captured under a new logging category called `user`. Successful logins are logged at the `info` level, while failed login attempts are logged at the `warning` level.

### Management Plugin 

#### Removed `unsafe-inline` and `unsafe-eval` CSP Directives

The Management UI's Content Security Policy (CSP) has been hardened by removing the `unsafe-inline` and `unsafe-eval` directives. Removing these directives prevents the execution of inline scripts and styles, significantly mitigating the risk of Cross-Site Scripting (XSS) attacks.

#### Configurable `Referrer-Policy` Header

The Management UI now supports configuring the `Referrer-Policy` HTTP response header via the `management.headers.referrer_policy` setting.

#### Optional `.json` Extension Requirement for Definition Uploads

Some deployments require strict filename extension validation when uploading definition files.
When enabled, both the Management UI and the server will validate that the uploaded file has a `.json` extension. 

This behavior is controlled by the new `management.require_definition_json_extension` configuration setting, which defaults to `false` for backwards compatibility. Regardless of this setting, the server always validates that the uploaded content is valid JSON before importing it.

#### Option to Hide the `Allow` Response Header

When `management.http.hide_allow_header` is set to `true`, the `Allow` HTTP response header is omitted from all responses (including `200 OK` responses to `OPTIONS` requests). This prevents the disclosure of supported HTTP methods to clients. The header will only be included in `405 Method Not Allowed` responses, as required by the HTTP specification.

#### Encrypted Basic Authentication Credentials

When `management.credentials_encryption_secret` is configured, the Management UI login endpoint (`POST /api/login`) validates the submitted username and password as usual. However, instead of the browser caching the raw base64-encoded credentials, the server encrypts them using AES-256-GCM with a key derived from the configured secret. This ciphertext is returned to the browser as an opaque token (prefixed with `rmqe.`). The browser then stores and presents this encrypted token on all subsequent requests via the `Authorization: Bearer rmqe.<token>` header.

**Important Upgrade Note:** When enabling this feature during a rolling cluster upgrade, it is highly recommended to upgrade all nodes before allowing users to access the Management UI. This is especially important in environments using a load balancer, as older nodes will not recognize the new encrypted tokens and will reject the requests, resulting in users being unexpectedly logged out.

### Dependency Changes

 * `ra` was upgraded to [`3.1.10`](https://github.com/rabbitmq/ra/releases/tag/v3.1.10)
